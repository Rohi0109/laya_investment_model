

“So what I wanted to play around with here was the idea of these smaller ‘System 1’ decision models — basically models optimized for very fast, constrained decisions rather than generating a bunch of text.
I wanted a relevant use case, so I built this little asset-manager dashboard. It takes a portfolio, pulls three of the most relevant recent news articles for each ticker, and then gets a quick ‘knee-jerk’ assessment of each article’s market reaction and whether it’s actually about the company or just broader sector noise.
The model I’m using is Laya. It’s an open-source decision model built on an encoder architecture, and it’s only around 421 million parameters. So compared with the huge generative models we normally talk about, it’s tiny — I can run the entire thing locally on my Mac or my ThinkCentre. No api needed!
The thing I really like about this class of model is the constrained output. I’ve worked on production agentic systems before where half the battle is making sure a generative model consistently gives you the schema you expect. Here I define the possible choices up front — bullish, bearish, neutral, whatever — and the model has to return one of those choices rather than generate arbitrary text.
So if I hit Analyze News here, each article gets evaluated independently. That gives me traceability — I can see which article was bullish, which was neutral, and which ones were actually about the company versus just sector-wide commentary — and then I aggregate those signals based on how relevant each article actually is to NVIDIA.
And because the model is so small, the actual inference is basically instantaneous. That’s where I think this gets interesting: not replacing deep research or a frontier model, but doing that first-pass triage incredibly cheaply and quickly across a huge stream of information. 
I actually started by trying to make it evaluate whether a stock was a good investment, and it was pretty terrible at that. So I built some regression cases around where it failed and narrowed the problem down to something it was actually good at: constrained classification of short pieces of evidence.
I also tried feeding it full transcripts. It can handle longer inputs with chunking, but that started defeating the whole speed advantage for this particular demo. So I ended up landing on short news events as the sweet spot.
And if I were productionizing this, I’d use this as the cheap routing layer. Most events get classified locally, and only the small percentage that are genuinely material get escalated to an analyst or a more expensive reasoning model.”
